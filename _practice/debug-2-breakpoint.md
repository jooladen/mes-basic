## 0. 이 문서를 다 읽으면 할 수 있는 것

- 처음 보는 이름(`render` 등)이 **라이브러리 것인지, 프로젝트가 만든 것인지** 판별한다
- 한 줄에 여러 동작이 섞인 코드를 **단계별로 쪼개서** 읽는다
- 크롬 개발자도구에서 **원하는 시점에만** 멈추고, 그때의 변수 값을 확인한다
- 멈추지 않고 **로그포인트**로 값을 찍는다
- 확인 결과를 보고 **범인인지 아닌지** 판정한다
- 실험이 끝나면 **깨끗하게 되돌린다**

## 1. 디버깅 전 3원칙

### 원칙 1. 머릿속 코드가 아니라 **실제 파일**을 읽는다

사람 눈은 "당연히 이렇겠지" 하고 틀린 글자를 맞게 읽어 버립니다.
실제로 이 연습 중에 **질문에 적은 코드와 실제 파일이 한 단어 달랐던 일**이 있었어요.

- 코드를 옮길 때는 **타이핑하지 말고 복사**한다
- 에디터 탭에 **●(저장 안 됨)** 표시가 있으면, 보고 있는 코드가 디스크의 파일과 다르다
- 의심되면 `git diff`로 커밋 버전과 비교한다

### 원칙 2. 표가 이상하면 **rows냐 columns냐**부터 정한다

`ItemPage.jsx` 맨 아래를 보면 표에 들어가는 재료는 **딱 두 개**입니다.

```jsx
<DataTable columns={columns} rows={rows} ... />
```

| 갈래 | 뜻 | 이렇다면 증상은? |
|---|---|---|
| **rows** | 데이터가 애초에 틀리게 왔다 | 필터·건수도 틀려야 한다 |
| **columns** | 데이터는 맞는데 **그리는 방법**이 틀렸다 | 필터는 맞고 글자만 틀린다 |

- columns는 **헤더만이 아닙니다.** 칸마다 `header`(제목)와 `render`(칸 안의 글자를 어떻게 보여 줄지)가 같이 들어 있어요.
- 데이터에 코드값(`RAW`)이 저장된 건 **정상**입니다. 코드를 한글로 바꿔 보여 주는 건 **columns의 `render`가 할 일**이에요.
- 한쪽이 범인이라고 판단되면 **다른 쪽 파일은 안 열어도 됩니다.** 볼 곳이 절반으로 줄어요.

### 원칙 3. 처음 보는 이름은 **import 경로로 출처를 판별**한다

| import 경로 시작 | 뜻 | 예 |
|---|---|---|
| `'react'`처럼 **이름으로 시작** | `node_modules`의 외부 라이브러리 | `import { useState } from 'react'` |
| `'@/...'` | 이 프로젝트의 `src/` (직접 만든 것) | `'@/common/components/table/DataTable'` |
| `'./'`, `'../'` | 이 프로젝트의 옆 파일 (직접 만든 것) | `'../services/itemService'` |

`@` = `src`라는 건 `jsconfig.json`의 `"@/*": ["./src/*"]`와 `vite.config.js`의 `'@': ... './src'`에 적혀 있습니다.

**판별 기준**: 그 이름을 **꺼내서 부르는 코드**가 어디 있나?
- 내 `src` 안에 보이면 → 프로젝트가 정한 약속
- `node_modules` 안에만 있고 내 코드에는 넘기는 코드만 있으면 → 라이브러리 약속

예: `DataTable.jsx`에 `col.render ? col.render(row) : row[col.key]`가 **직접 보인다** → `render`는 이 프로젝트가 정한 이름입니다.
참고로 shadcn은 코드를 프로젝트 안으로 **복사해 주는 도구**라 `@/common/components/ui/` 아래에 있고, `ui/table.jsx`에는 `render`가 한 번도 안 나옵니다.

### 참고: 함수도 값이다 (일급 함수)

```js
{ key: 'itemType', header: '유형', render: (row) => typeLabel(row.itemType) }
//                                  ~~~~~~   ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
//                                  프로퍼티 키  프로퍼티 값 = 함수
```

| 준의 표현 | 공식 용어 |
|---|---|
| 함수도 밸류다 | **일급 함수 (First-class Function)** |
| 키:밸류 | **객체의 프로퍼티** (프로퍼티 키 / 프로퍼티 값) |
| 넣어 두면 받은 쪽이 나중에 불러 줌 | **콜백 함수 (Callback)** |
| 함수를 받거나 리턴하는 함수 | **고차 함수 (Higher-order Function)** — `find`, `map`, `buildColumns` |

Java로 쓰면 `Map<String, Object>`에 `put("render", 람다)` 하고, 받는 쪽이 `get("render")`해서 `apply(row)` 하는 것과 같습니다.

## 3. 한 줄짜리 코드 쪼개 읽기

### 3-1. 동작 3단계

```js
const typeLabel = (value) => itemTypeCodes.find((c) => 비교식)?.label ?? value
```

| 단계 | 코드 | 하는 일 | 실패하면 |
|---|---|---|---|
| ① | `itemTypeCodes.find((c) => 비교식)` | 코드 목록에서 조건에 맞는 것 **하나 찾기** | `undefined` |
| ② | `?.label` | 찾은 것의 **한글 이름 꺼내기** | 앞이 `undefined`면 에러 없이 `undefined` |
| ③ | `?? value` | 결과가 없으면 **원래 값을 그대로** 돌려주기 | — |

화면에 `RAW`가 나온다 = **③까지 떨어졌다** = ①에서 **못 찾았다**.
그래서 질문은 하나입니다. **①의 비교식이 무엇과 무엇을 비교하고 있나?**

> 이런 체이닝(`find → ?. → ??`)은 실패해도 **예외가 안 나고 조용히 기본값으로 떨어집니다(silent fallback).** 에러가 없어서 찾기 어려운 버그가 됩니다.

### 3-2. 한 줄 안의 "멈출 수 있는 위치" 3곳

```js
const typeLabel = (value) => itemTypeCodes.find((c) => 비교식)?.label ?? value
//    ▲ A                    ▲ B                  ▲ C
```

| 위치 | 언제 실행되나 | 멈추면 `value`가 보이나? |
|---|---|---|
| **A** `const typeLabel =` | 화면이 그려질 때마다 **함수를 만들기만** 함 | ❌ 호출 전이라 `value`가 없음 |
| **B** `itemTypeCodes.find(...)` | `typeLabel('RAW')`가 **실제로 호출될 때** | ⭕ **원하는 시점** |
| **C** `(c) => 비교식` 안쪽 | find가 코드 목록을 **하나씩 돌 때마다** (3번) | ⭕ `c`와 `value` 둘 다 보임 |

줄 번호를 그냥 클릭하면 크롬은 **A에 멈춥니다.** 그래서 처음 멈췄을 때 `value`가 없습니다.

## 4. 왜 같은 줄에서 여러 번 멈추나

화면은 한 번만 그려지지 않습니다. 아래 순서로 **여러 번 다시 그려져요.**

| 순서 | 상황 | `typeLabel`이 호출되나? |
|---|---|---|
| 1 | 첫 렌더. `useCodes`의 코드 목록 `[]`, `useSearch`의 `rows` `[]` | ❌ 표에 줄이 없으니 안 부름 (A에서만 멈춤) |
| 2 | 같은 렌더를 한 번 더. `main.jsx`의 `<StrictMode>`가 **개발 모드에서 일부러 2번** 그림 | ❌ |
| 3 | 코드 목록 또는 표 데이터 중 **먼저 온 쪽**이 도착 → 다시 그림 (mock에 지연이 있어서 순서는 매번 다를 수 있음) | 표 데이터가 아직이면 ❌ |
| 4 | **표 데이터 도착** → DataTable이 줄마다 `render` → `typeLabel(row.itemType)` | ⭕ 여기서부터 B·C에 멈춤 |

- A에 걸면 F8을 **서너 번** 눌러야 `value`가 보입니다.
- B에 걸어도, 코드 목록이 아직 `[]`인 렌더에서 멈출 수 있습니다. 그때는 **F8 한 번 더**.
- 표 데이터가 여러 줄이면 **줄 수만큼** 호출됩니다. StrictMode 때문에 그 두 배가 될 수도 있습니다.

> 운영 빌드(`pnpm build`)에서는 StrictMode의 이중 렌더가 없습니다. 개발 모드에서만 두 번 그려집니다.

## 5. 방법 1 — 인라인 브레이크포인트 (추천)

### 5-1. B 위치에만 걸기

1. Sources에서 `ItemPage.jsx`의 `typeLabel` 줄을 찾는다
2. **줄 번호를 클릭** → 파란 표시가 생기고, 그 줄 코드 안에 **작은 화살표 표시가 여러 개** 나타난다
3. `itemTypeCodes.find` **바로 앞의 화살표만 파란색으로** 남긴다
4. 나머지 화살표(특히 줄 맨 앞 = A)는 **클릭해서 회색으로** 끈다
5. **F5** 새로고침

이제 `typeLabel`이 **실제로 호출될 때만** 멈춥니다.

### 5-2. 멈췄을 때 "맞는 시점"인지 확인

오른쪽 패널 **Scope → Local**을 봅니다.

| 보이는 것 | 판정 |
|---|---|
| `value: "RAW"` 가 있다 | ⭕ 맞는 시점 |
| `value`가 없다 | ❌ A에 멈춘 것 → 5-1의 3~4번을 다시 |
| `value`는 있는데 `itemTypeCodes`가 `[]` | 코드 목록이 아직 안 온 렌더 → **F8** |

`itemTypeCodes`는 Scope → **Closure**(바깥 함수의 변수) 쪽에 보일 수 있습니다.

### 5-3. Console에서 값 찍기

멈춘 상태에서 **Esc**를 누르면 아래에 Console 창이 열립니다.
멈춘 동안에는 **그 시점의 변수를 Console에서 그대로 쓸 수 있어요.** 한 줄씩 입력합니다.

```js
value                                           // 지금 번역하려는 값
itemTypeCodes                                   // 코드 목록 전체 ([] 이면 아직 안 온 것)
itemTypeCodes[0]                                // 코드 하나의 모양 → { value: ..., label: ... }
itemTypeCodes.find((c) => c.value === value)    // value 이름표로 찾기
itemTypeCodes.find((c) => c.label === value)    // label 이름표로 찾기
```

마지막 두 줄의 결과를 비교합니다. 그리고 **에디터에서 실제 파일의 비교식**을 보고, 둘 중 어느 쪽과 같은지 확인합니다.

### 5-4. C 위치로 들어가서 하나씩 보기 (선택)

B에서 멈춘 상태에서 **F11**(Step into)을 누르면 find에 넘긴 `(c) => 비교식` 안으로 들어갑니다.
Scope에 `c`가 보이고, **F11/F10**을 누를 때마다 다음 `c`로 넘어갑니다.
`c`의 어느 칸과 `value`를 비교하는지 **눈으로 3번** 확인할 수 있어요.

### 5-5. 단축키

| 키 | 이름 | 하는 일 |
|---|---|---|
| **F8** | Resume | 다음 브레이크포인트까지 그냥 달림 (다음 줄의 `typeLabel` 호출로) |
| **F10** | Step over | 지금 줄을 실행하고 다음 줄에서 멈춤 |
| **F11** | Step into | 부르는 함수 **안으로** 들어감 |
| Shift+F11 | Step out | 지금 함수에서 빠져나옴 |
| Ctrl+F8 | Deactivate | 모든 브레이크포인트를 잠시 끔 |

## 6. 방법 2 — 로그포인트 (멈추지 않고 찍기)

코드를 **안 고치고** console.log를 찍는 기능입니다. 흐름 전체를 보고 싶을 때 좋아요.

1. `typeLabel` 줄 번호를 **우클릭** → **Add logpoint**
2. 입력: `'[typeLabel]', value, itemTypeCodes.length`
3. 5-1처럼 **B 위치의 화살표**에만 남기기
4. F5 → **Console** 탭에 호출마다 한 줄씩 찍힘

확인할 것:
- 몇 번째 렌더부터 `value`가 들어오는가 (4장의 타임라인 확인)
- `itemTypeCodes.length`가 `0`인 호출이 있는가 (코드 목록이 늦게 온 경우)

> 로그포인트가 A 위치에 걸리면 `value is not defined` 같은 에러가 찍힙니다. 이것도 "A에서는 `value`가 없다"는 증거예요.

## 7. 방법 3 — console.log (코드 수정)

브레이크포인트가 불편할 때 쓰는 방법입니다. 한 줄짜리 화살표 함수는 중간값을 못 찍으니 `{ }` 블록으로 풉니다.

**비교식은 반드시 파일에 있는 것을 그대로 복사**하세요. 다른 걸 쓰면 테스트가 의미 없어집니다.

이 블록이 없으면 find가 무엇을 찾았는지(또는 못 찾았는지) 안 보이고, 최종 결과 `RAW`만 보입니다.

```js
const typeLabel = (value) => {
  // DEBUG: find 결과를 보기 위해 한 줄짜리를 3단계로 쪼갬 (확인 후 원래 한 줄로 되돌릴 것)
  const found = itemTypeCodes.find((c) => /* ← 파일에 있는 비교식 그대로 복사 */)
  console.log('[typeLabel]', { value, first: itemTypeCodes[0], found })
  return found?.label ?? value
}
```

- 저장하면 Vite가 화면을 자동으로 새로 고칩니다
- F12 → **Console** → 필터 칸에 `[typeLabel]` 입력하면 이 로그만 보임
- 확인이 끝나면 **원래 한 줄로 되돌리기** → 8장 뒷정리

## 8. 결과 해석

| `found` (또는 find 결과) | 뜻 | 다음 할 일 |
|---|---|---|
| `{ value: 'RAW', label: '원자재' }` | 찾았다 → `typeLabel`은 **무죄** | `render` 연결(`buildColumns`)이나 `DataTable` 쪽을 다시 봄 |
| `undefined` | **못 찾았다** → ③으로 떨어져 `RAW` 출력 | `value`와 `itemTypeCodes[0]`를 나란히 놓고 **비교식이 어느 칸끼리 비교하는지** 확인 |
| `itemTypeCodes`가 계속 `[]` | 코드 목록 자체가 안 옴 | `useCodes` → `codeRepository` 쪽 조사 (단, 02번은 **선택 박스에 한글이 잘 나오므로** 이 경우가 아님) |

범인을 찾았다면 답안에 이렇게 적습니다.
- **5번 범인**: 파일 + 함수/변수 이름 (줄 번호가 아니라 **이름**으로)
- **6번 수정안**: 무엇을 무엇으로 바꾸는지 + **왜**
- **7번 확인**: 고친 뒤 유형 칸이 한글로 나오는지 + **유형 필터가 여전히 제대로 걸리는지** + `pnpm test` 통과

## 9. 자주 막히는 곳 FAQ

**Q. 멈췄는데 Scope에 `value`가 없어요.**
A. 줄 맨 앞(A)에 멈춘 겁니다. 5-1대로 `find` 앞의 인라인 화살표에만 거세요.

**Q. F8을 여러 번 눌러야 `value`가 나와요.**
A. 정상입니다. 4장의 타임라인처럼 첫 렌더들에서는 표 데이터가 `[]`라 `typeLabel`이 안 불립니다. StrictMode 때문에 두 번씩 그려지기도 합니다.

**Q. `itemTypeCodes`가 `[]`로 나와요.**
A. 코드 목록이 아직 도착하기 전의 렌더입니다. F8로 다음 호출까지 넘어가세요.

**Q. 크롬의 줄 번호가 에디터와 달라요.**
A. Vite가 변환한 코드라서 그렇습니다. `typeLabel`이라는 **이름**으로 찾으세요.

**Q. 소스가 저절로 바뀐 것 같아요.**
A. `git diff`로 확인하세요. 커밋 이후 누가 바꿨는지는 git이 알려 주지 않습니다. 에디터에 **저장 안 한 수정본(●)**이 있는지도 보세요. 되돌리려면 `git checkout -- <파일>`을 쓰고, 이때 에디터 탭에 ●가 있으면 **저장하지 말고 닫은 뒤** 다시 여세요.

**Q. 브레이크포인트를 걸었는데 아예 안 멈춰요.**
A. ① Ctrl+F8로 전체 비활성화돼 있지 않은지(Sources 오른쪽 위 아이콘) ② 화면에서 **조회**를 눌러 다시 그리게 했는지 ③ 품목관리 화면이 맞는지 확인하세요.

**Q. 처음 보는 이름이 나왔어요.**
A. 1장 원칙 3 순서대로 하세요. import 경로 확인 → **F12(정의로 이동)**, **Shift+F12(참조 찾기)** → 파일 맨 위 주석 → 값을 잠깐 바꿔 보는 실험.
